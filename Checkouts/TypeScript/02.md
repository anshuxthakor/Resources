## 2. The Restaurant-Order Analogy

Think of the earlier `sum(a, b)` as a menu with **exactly two slots** — you can only order two things. Rest parameters turn that into an **open order pad**: the waiter (function) will write down as many items as you hand over, however many that is.

```
sum(67, 78, 90, 87, 6, 5, 4, 3, 2, 6, 4, 5, 6)
     ↑ order pad collects all 13 items into one list called `rest`
```

---

## 3. The Code

```ts
let sum = (...rest: number[]): number => {
  let data = rest.reduce((a, v) => a + v, 0);
  return data;
};

let res = sum(67, 78, 90, 87, 6, 5, 4, 3, 2, 6, 4, 5, 6);
console.log(res);
```

### 3.1 `...rest` — The Rest Parameter

- The `...` before a parameter name means **"gather every remaining argument into a single array."**
- No matter how many arguments you pass — 0, 1, or 100 — they all land inside one array called `rest`.
- In TypeScript, `...rest: number[]` types that array explicitly: `rest` is guaranteed to be an **array of numbers**, so calling `sum(67, "78")` would be a compile-time error — the JS version has no such guard.
- A rest parameter **must be the last parameter** in the list (you can have `(a, b, ...rest)` but never `(...rest, a, b)`), since it greedily consumes everything after it.

### 3.2 Rest vs Spread — Same `...`, Opposite Direction

This is the detail most people mix up, so worth locking in:

| | Rest (`...`) | Spread (`...`) |
|---|---|---|
| **Used in** | Function **parameters** | Function **calls** / arrays / objects |
| **Direction** | **Collects** many values → into one array | **Expands** one array → into many values |
| **Example** | `(...rest) => {}` — gathers arguments *in* | `sum(...[1, 2, 3])` — unpacks an array *out* |

Same three dots, opposite job — the position (parameter list vs argument list) tells you which one you're looking at.

### 3.3 `reduce` — Folding the Array Down to One Number

```ts
rest.reduce((a, v) => a + v, 0);
```

- `reduce` walks the array **one value at a time**, carrying an accumulator forward.
- `(a, v) => a + v` — the callback: `a` is the accumulator (running total so far), `v` is the current array element.
- `0` — the **initial value** of the accumulator, passed as `reduce`'s second argument. Without it, `reduce` would start `a` as the array's first element instead, which happens to still work for addition but is a habit worth being deliberate about (it breaks for operations like multiplication-from-zero, or when the array could be empty — an empty array with no initial value throws).

**Trace for a short example**, `[67, 78, 90]`:

```
step 1: a = 0,  v = 67  →  a + v = 67
step 2: a = 67, v = 78  →  a + v = 145
step 3: a = 145, v = 90 →  a + v = 235
final: 235
```

Same mechanism, just running across all 13 numbers in your actual call → `res = 363`.

## 4. `index.ts` → `index.js` — What TypeScript Erased

Comparing your two files side by side, the *only* difference in the live code is one type annotation:

```diff
- let sum = (...rest: number[]): number => {
+ let sum = (...rest) => {
```

```
: number[]   →  gone   (parameter type)
: number     →  gone   (return type)
```

This is **type erasure** in action: `number[]` and the return type `: number` exist purely for the compiler to check your code *before* it runs — they carry zero meaning to the JavaScript engine, so `tsc` strips them out entirely when it compiles down to `index.js`. The runtime logic (`reduce`, the arrow function body, the actual `console.log`) is byte-for-byte identical between the two files.

## 5. Quick Summary

```
...rest          → gathers all arguments into one array (parameters)
...arr            → unpacks one array into many values (calls) — opposite of rest
rest: number[]    → TS-only: enforces every argument is a number
reduce(fn, init)  → fn(accumulator, currentValue), init = starting accumulator
                     runs once per array element, returns the final accumulator

TS compiles to JS by ERASING types only —
the actual logic/behavior never changes between .ts and .js
```
